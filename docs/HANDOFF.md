# 작업 인계 메모

기준: 2026-10-15 / `feature/21_diary_my_figma`

## 최근 수정

`f443b36` — 분석 중 일기 작성으로 이동한 뒤 홈에 돌아올 때 화면과 분석 상태가 꼬이는 문제를 수정했습니다.

- 일기로 이동할 때 홈 위에 쌓인 촬영·업로드·로딩 화면을 제거합니다. 일기 저장이나 뒤로가기로 분석 화면에 복귀하지 않습니다.
- 분석 작업은 Activity 범위의 `AnalysisViewModel`에서 유지합니다. 일기로 이동해도 현재 Activity가 살아 있는 동안 계속됩니다.
- 분석 버튼을 누를 때 요청 ID를 새로 생성합니다. 같은 요청의 로딩 화면이 복원되면 완료·실패 상태까지 그대로 관찰하고 재업로드하지 않습니다.
- 같은 영상을 명시적으로 다시 분석하거나 오류 화면에서 재시도하면 새 작업을 시작합니다.
- 새 분석은 이전 클라이언트 작업을 취소하며, 이전 작업의 응답은 새 상태를 덮지 못합니다. 서버에서 이미 시작한 작업을 취소하는 API는 호출하지 않습니다.
- 시연용 지연도 ViewModel로 이동해 로딩 화면 종료로 끊기지 않게 했습니다.

관련 코드: `app/src/main/java/kr/ac/anu/mumu/presentation/analysis/`

## 분석 모드

`AnalysisConfig.kt`의 현재 설정:

- `DEMO_MODE = false`: 실제 서버 분석을 요청합니다.
- `DEMO_LOADING_MILLIS = 9_000L`: 시연 모드를 켰을 때 9초 후 임시 결과를 만듭니다.
- 시연 결과는 서버에 저장되지 않으므로 서버 기반 분석 내역에 추가되지 않습니다.
- 이 스위치는 빌드 종류와 무관합니다. 시연 후에는 `false`로 되돌려야 합니다.

실제 분석 요청과 결과 조회는 `AnalysisRepositoryImpl.kt`에 있습니다. 분석 후 다른 화면으로 이동했다면 홈의 내역에서 서버 결과를 조회할 수 있습니다.

## 검증 결과

2026-10-15 수정 코드에서 다음 작업을 통과했습니다.

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:ktlintCheck
```

전체 단위 테스트 14개 중 분석 회귀 테스트 5개:

1. 같은 요청으로 화면에 복귀해도 진행 중·완료된 분석을 다시 요청하지 않음.
2. 같은 영상도 새 요청 ID로 분석하면 다시 실행됨.
3. 이전 요청이 취소를 무시하고 완료돼도 새 결과를 덮지 않음.
4. 실패 후 화면 복원만으로 재요청하지 않고 명시적인 재시도만 실행함.
5. 시연 분석이 화면과 분리되어 9초 후 완료되며 중간 복귀로 타이머가 초기화되지 않음.

연결된 기기가 없어 실제 화면 전환은 아직 확인하지 않았습니다. 자동 테스트는 분석 상태 로직을 검증하며 실제 내비게이션이나 서버 성공을 보장하지 않습니다.

## 다음 확인 순서

1. 실기기에서 `홈 → 촬영 또는 파일 선택 → 분석 중 일기 쓰기 → 저장/뒤로가기 → 홈`을 확인합니다. 이전 로딩·촬영 화면으로 돌아가거나 결과 화면이 갑자기 뜨지 않아야 합니다.
2. 분석 중·완료 후 화면 회전, 연속 분석, 오류 후 재시도, 일기/홈 탭 반복 이동을 확인합니다.
3. 실제 서버 분석 성공을 검증합니다. 이전에는 결과 조회에서 서버의 `FAILED` 상태가 관찰됐으며 AI 처리 로그 확인이 남아 있습니다.
4. 영상 썸네일 표시와 영상 준비 완료 시점의 경쟁, 화면 종료 후 미리보기 접근 가능성을 점검합니다.

Activity/프로세스가 종료된 후 진행 중인 분석을 ID로 이어받는 기능은 아직 없습니다. 서버 내역을 통해 결과를 확인해야 합니다.

## 환경을 옮길 때

- SDK 경로, 계정 세션, 기기 내 선택 영상과 캐시, 빌드 결과물은 Git으로 이동하지 않습니다.
- 환경마다 자동 생성한 debug 서명 키가 다르면 기존 APK에 업데이트 설치할 수 없습니다. 기존 앱 데이터를 보존해야 한다면 같은 서명 키를 별도 안전한 경로로 준비합니다. 키는 저장소에 추가하지 않습니다.
- 다른 환경에서 변경사항을 커밋·푸시한 다음 현재 환경에서도 `git pull --ff-only`로 동기화하고 작업합니다.
